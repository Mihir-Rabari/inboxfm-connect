---
title: 'Test Connection (Health Check)'
openapi: POST /v1/connections/{id}/test
---

Verify that an existing connection is active, healthy, and usable before an AI agent, workflow, REST request, or MCP tool executes actions against it.

### Description

Performs a lightweight, non-destructive health check against the target integration with the stored credentials:
1. Validates connection existence and access permissions for the caller's project.
2. Checks token staleness and automatically executes OAuth / custom-auth token refreshes when expired.
3. Submits an isolated authentication validation to the integration engine.
4. Updates the connection status (`ACTIVE` vs `ERROR`) accordingly.
5. Returns a structured health check result including response time and status.

### Response

```json
{
  "success": true,
  "status": "HEALTHY",
  "message": "Connection is healthy and working.",
  "testedAt": "2026-09-28T12:00:00.000Z",
  "responseTimeMs": 142
}
```

### Health Status Values

| Status | Description |
|---|---|
| `HEALTHY` | Credentials verified and integration is responsive |
| `AUTH_EXPIRED` | Credentials/tokens expired and automatic refresh was unsuccessful |
| `AUTH_INVALID` | Invalid or revoked credentials |
| `INSUFFICIENT_PERMISSION` | Missing scopes or insufficient account permissions |
| `RATE_LIMITED` | Provider rate limit exceeded |
| `PROVIDER_ERROR` | Upstream provider outage or 5xx server error |
| `NETWORK_ERROR` | Network timeout or unreachable host |

### Security

- Never returns sensitive tokens, passwords, or decrypted secrets in response payloads or error logs.
- Enforces project and platform tenant isolation.
